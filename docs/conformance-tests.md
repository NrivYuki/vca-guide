# 対応表とテストの対応

[conformance.md](conformance.md) の各行を、どのテストが確かめているかの一覧です。`tools/trace.js` がテストを実行して作るもので、手で直さないでください(`npm run trace` で作り直す)。GitHub Actions は、この一覧が古くないこと、◎ の行にテストがあること、テストがすべて通ることを確かめます。

確かめ方の種類は次のとおりです。1 つのテストが複数の行・種類にまたがることがあります。

| 種類 | 意味 |
|---|---|
| 正常 | 正しいデータ・手順で、期待どおりに動くこと |
| 異常 | 誤ったデータ・手順を、警告・エラー・中止で正しく扱うこと |
| 境界 | 上限・下限・ちょうどの値(80 文字、6 秒、送り直し 3 回など)での動き |
| 規格の例 | 規格書に載っている例(附属書 B・C、本文の例)と一致すること |
| Simulator | DCS Host Simulator との照合で見つかった場面 |

テストは全部で 183 件です(正常 90・異常 88・境界 43・規格の例 13・Simulator 3)。

## 行ごとのテスト

### 3.2

予約文字(FS・GS・RS・ACK・NAK・ESC など)

- 予約文字は ESC と最上位ビットを立てた値に、普通の文字はそのまま。16 ビットの値は下位バイトが先(5.4.16)(正常、tests/tests.js)
- エスケープ: 全 256 バイトで往復一致(境界、tests/tests.js)

### 3.3

データ型(数値・整数・literal・text・limited)

- 左右レコードの取り出し(片眼のみ・単一値・不明値)(正常・境界、tests/tests.js)
- 数値の読み取りは厳密(後ろに文字が付いた値は数値として扱わない)(異常、tests/tests.js)
- データ型: limited は 12 文字まで、ASCII 以外の文字、255 文字を超える値(境界・異常、tests/tests.js)
- 余分な区切りを許し、小数点の桁数によらず読む(5.1・A.1.1.5.1)(正常・境界、tests/tests.js)
- 整数の欄に小数点は書かない(A.1.1.5.2)(異常、tests/tests.js)

### 3.4-3.7

メッセージ・レコード・セッション・タイムアウトの定義

- アップロード(7.3): 要求 → 応答 → データ → 応答、CRC 付き(正常、tests/session-tests.js)
- ダウンロード(7.4): 要求 → データ、JOB を確かめる(正常、tests/session-tests.js)
- 確認応答が 6 秒来なければ中止し、送り直さない(6.1.3.2)(境界、tests/session-tests.js)
- ACK のあと 12 秒パケットが来なければ中止(6.1.3.3)(境界、tests/session-tests.js)
- パケットの途中で 5 秒止まれば中止(6.1.3.4)。そのあともホストは次の要求を受け付ける(8.2)(境界・異常、tests/session-tests.js)
