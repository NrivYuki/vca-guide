# 規格の義務の一覧

DCS v3.14 の本文と附属書 A から、守る決まりを書いた文を 1 つずつ取り出し、このリポジトリでの扱いを決めた一覧です。次の 3 つに分けています。

- [義務](#義務)(R): 「しなければならない」(shall・must)と「してはならない」(shall not・must not)を含む文。241 文
- [推奨](#推奨)(S): 「するのがよい」(should)を含む文。104 文。守らなくても規格に反しないので、受け取ったデータの警告にはしない。ライブラリ自身の動き(読み取りの許容、送り直し、初期化のデータなど)に関わるものは、テストで確かめる
- [ほかの言い方の義務](#ほかの言い方の義務)(O): shall・must・should を使わずに義務や禁止を書いた文(is required、may not、not allowed、mandatory など)。67 文。説明の文(「するもの」の意味の is to be など)も機械的に拾っているので、扱いを「説明」にした

取り出し方と読み方:

- 規格書 PDF のテキストから、上の言葉を含む文を機械的に取り出した(附属書 B・C・D は除く。表の説明欄は含む)。表の説明や例(図)も含まれ、同じ内容が重なるものもある。節の欄は、取り出しで表の位置がずれたものを、規格書に合わせてある
- 「要点」は、規格の文を読んだうえで要点を日本語で書き起こしたもので、翻訳ではない。正確な定義は規格書の該当の節で確かめること
- 「テスト」の文は、テストに番号を書いてある(`test(名前, { spec, kind, req: [番号] }, …)`)。`tools/trace.js` が、「テスト」の文にテストがあること、テストに書いた番号がこの一覧の「テスト」の文にあることを GitHub Actions で確かめる。どのテストかは [conformance-tests.md](conformance-tests.md#義務ごとのテスト) にある

## 扱いの種類

| 扱い | 意味 | 義務 | 推奨 | ほかの言い方 |
|---|---|---|---|---|
| テスト | このライブラリが確かめ、テストがある | 146 | 30 | 23 |
| 利用者 | ライブラリはデータを読み書きするだけで、中身を決めるアプリが守る(データからは確かめられない理由を書いた) | 21 | 32 | 1 |
| 機器 | 加工機など、装置の動きの決まり | 16 | 8 | 0 |
| 対象外 | このリポジトリが扱わない機能(面形状の暗号化、LDS・LMS のファイルの運用、シリアル接続、TOKEN による課金、レンズ設計システム、画面の表示) | 44 | 8 | 5 |
| 未対応 | ライブラリで確かめられるが、まだ確かめていない | 0 | 0 | 0 |
| 説明 | 規格の説明・注記・例で、守る対象が無い | 14 | 26 | 38 |
